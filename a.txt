2. Change the floating-point output handling
Your firmware formats sensor values using statements such as:
snprintf(line, sizeof(line),
         "%lu,%.5f,%.5f,%.5f,%.4f,%.4f,%.4f,%.2f\r\n",
         (unsigned long)timestamp, ax, ay, az, gx, gy, gz, temp_c);


The problem is that STM32CubeIDE projects commonly use the size-optimized C library, which may not include floating-point support for printf/snprintf by default.
Required action: Open Project Properties and check the linker settings. If the project uses Newlib Nano without floating-point formatting enabled, add this linker option:
-u _printf_float


Then rebuild the project. Without this support, the program may compile but the decimal sensor readings may not be formatted correctly.
3. Improve the sensor sampling configuration
Your current code sets:
ICM20608_WriteReg(ICM_REG_SMPLRT_DIV, 9U);


With the configured digital low-pass filter, this sets the nominal sensor output rate to 100 Hz.
However, TIM2 also reads the sensor at 100 Hz. The two clocks are not synchronized, so occasional repeated or skipped sensor samples are possible.
For more reliable 100 Hz host acquisition, I recommend changing this to:
ICM20608_WriteReg(ICM_REG_SMPLRT_DIV, 0U);


This configures the nominal sensor output rate to 1 kHz with the selected filter settings, while TIM2 continues to read and transmit at 100 Hz. The laptop still receives data at the intended rate.
Make this change in ICM20608_Init(), retaining the existing 10 ms timer interval.
4. Verify the timer and data transfer
Your TIM2 configuration is correct if the system clock is 72 MHz and APB1 is divided by two:
- Timer prescaler: 7199
- Timer period: 99
- Interrupt frequency: 100 Hz
- Target interval: 10 ms
The timer interrupt should only set the sampling flag. The I²C read and UART transmission should remain in the main loop, as they currently do.
One limitation remains: sample_due is a single flag, not a queue. If the main loop takes longer than 10 ms, timer events can be missed. The existing workload should be tested to confirm it consistently completes within the interval. If you require guaranteed timing, use buffered acquisition and non-blocking transmission.
